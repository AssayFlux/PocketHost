# Pocket Host v0.1.0 — Phase 2 verification

**Verification snapshot:** Current `Alpha` branch implementation; see live workflow evidence below.  
**Branch:** `Alpha` only  
**Date:** 2026-11-28  
**Release status:** NOT ACCEPTED — automated and owner-operated acceptance remains in progress.

## Scope

Phase 2 verifies that the v0.1.0 build works beyond source presence. Evidence is separated into automated CI, emulator execution, physical-device acceptance and real-network operation. A passing source compile or emulator suite is not a substitute for physical-device or public visitor evidence.

## Work added for verification

- Added `.github/workflows/android-emulator-acceptance.yml` to install the companion runtime worker and execute `:app:connectedDebugAndroidTest` on an API 35 x86_64 Android emulator.
- The existing instrumentation suite covers native loopback HTTP serving, site-root and symlink isolation, interrupted backup/restore recovery, management API authentication and pairing, relay lifecycle, and Python/Node runtime routing.
- Added the explicit Compose Foundation dependency after an earlier APK build exposed unresolved `Modifier.clickable` symbols.
- Android manifest review: only the launcher activity is exported; internal activities, receivers and services are non-exported. The app disables Android backup. Network security defaults to cleartext-disabled and permits cleartext only to 127.0.0.1.
- Management API source binds to 127.0.0.1, validates Host/Origin, bounds request headers/body and worker queues, requires approved pairing for initial owner sessions, and stores only token hashes in session state.
- Cloudflare token source passes the token through the child process environment rather than argv and redacts exact token occurrences from captured logs.
- ACME HTTP-01 implementation requires explicit terms acceptance and a non-loopback bind; real issuance still needs public TCP/80 reachability.

## Phase 2 implementation updates (2026-11-28)

The Alpha branch now includes the following additional implementation and verification work:

- Production console/API/visitor routing and deployment configuration are documented in [PRODUCTION_WEB_DEPLOYMENT.md](PRODUCTION_WEB_DEPLOYMENT.md).
- Android launcher resources are generated from the canonical `Assets/Pocket Host 7.svg` during `:app:preBuild`. The generator creates square 48dp legacy icons at mdpi/hdpi/xhdpi/xxhdpi/xxxhdpi, a white adaptive-icon background, and a centered adaptive foreground within Android's 66dp safe area.
- The icon generator checks expected raster dimensions and rejects transparent legacy launcher PNGs or missing white corner pixels before the Android build can continue.
- Android APK packaging verifies app/runtime package IDs, version metadata, APK signatures, matching app/worker signing certificates, and native library coverage for arm64-v8a, armeabi-v7a and x86_64.
- Android emulator acceptance now permits the TCG software-emulation fallback on hosted runners, uses an extended boot timeout, and installs the separate runtime-worker APK before running instrumentation.
- APK and emulator workflows are configured to rerun when the launcher SVG or buildSrc icon generator changes.

## Acceptance not performed

The following cannot be certified from repository source or hosted CI and require an owner-controlled physical Android device, a public gateway or reachable public IPv6 endpoint, domain/DNS control, deployment credentials and an independent external network:

1. Install/upgrade the APK on a physical Android device (record device model, Android version, ABI and APK SHA-256).
2. Import a real website from a folder and ZIP; edit files; preview; publish; rollback; export and restore.
3. Verify loopback and LAN access from a second device, then test multi-host routing and cross-site isolation.
4. Force-stop/kill the app, reboot the phone, change Wi-Fi/mobile networks and verify foreground service, hosting and relay recovery.
5. Run the trusted Python WSGI and Node workloads on-device, including stop/crash/restart and resource-bound behaviour.
6. Configure the selected public gateway and DNS provider (Cloudflare DNS records are sufficient; Cloudflare Tunnel is optional) and test an independent visitor over mobile data.
7. For direct Relay/ACME operation, verify public DNS ownership, inbound TCP/80 HTTP-01 challenge, certificate issuance, HTTPS visitor access, renewal and credential rotation/revocation across restart.
8. Test backup restore after interrupted operations and verify that the restored routes, settings and site files remain isolated.
9. Review Android battery/doze behaviour, foreground notification and permissions on the actual device.
10. Verify production signing only after protected release keystore credentials are configured. Current CI APKs are debug-signed and intended for testing only.

## Exit rule

Phase 2 remains **OPEN** until:

- current-head general quality, Android lint/JVM, three-ABI native/source validation, APK metadata/signature/payload verification and API 35 emulator instrumentation pass;
- owner reports physical-device tests with evidence;
- at least one real hostname is reachable over an independent external network with correct HTTPS and site routing;
- restart/recovery, backup/restore, access isolation and credential revocation are accepted; and
- no unresolved critical/high security issue remains.

Do not describe v0.1.0 as production-ready, device-verified or publicly operational before these gates are evidenced.
