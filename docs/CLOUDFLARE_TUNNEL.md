# Cloudflare Tunnel — Provider Specification

**Release assignment:** v0.1.0 — First Hosting  
**Current source status:** Android connector/token foundations exist; public hostname and external-network acceptance remain open.

## Purpose

Cloudflare Tunnel is an optional public-ingress provider. The Android host makes an outbound connection to an owner-created Cloudflare named tunnel. Cloudflare's edge receives visitors and forwards requests to the phone's local Rust HTTP origin. This can work when the phone is behind carrier NAT because the phone initiates the connection.

Cloudflare is not Pocket Host's own Relay system. It remains an optional fallback/provider and requires an owner Cloudflare account and tunnel.

## Existing repository integration

- `app/src/main/java/com/assayflux/pockethost/tunnel/CloudflareTokenStore.kt` stores the named-tunnel token using AES-GCM and Android Keystore.
- `CloudflareTunnelRuntime.kt` launches the Android-targeted cloudflared executable as an app-owned child process.
- The token is passed using the `TUNNEL_TOKEN` environment variable, not command arguments.
- The runtime checks the local cloudflared readiness endpoint and reports process/connection state.
- `HostingService.kt` supervises tunnel start/retry/stop with the hosting service lifecycle.
- Main app Settings > Network includes token save/remove and tunnel start/stop controls.
- `scripts/build-cloudflared-android.sh` builds the pinned upstream cloudflared source for arm64-v8a, armeabi-v7a and x86_64. The binary is generated by CI/build; it is not committed in the repository.
- Android integration CI built and verified cloudflared ELF architectures on source commit `5d90c1d`.

This proves source and build integration, not a live Cloudflare account, DNS route, valid public certificate or external visitor request.

## Owner configuration

Pocket Host does not currently create Cloudflare DNS records or public-hostname routes through the Cloudflare API. The owner must:

1. Create or reuse a named tunnel in their Cloudflare account.
2. Add the public hostname in Cloudflare Zero Trust / Tunnel configuration.
3. Point the hostname to the Android local Rust origin, normally `http://127.0.0.1:8080` (or the configured static-server port).
4. Configure the zone's HTTP-to-HTTPS behavior and edge TLS policy.
5. Paste the named-tunnel token into Pocket Host and save it securely.
6. Start the tunnel and independently test the real hostname from mobile data or another external network.

A connector reporting CONNECTED means the process has an active edge connection. It does not prove that the hostname route points to the correct origin or serves the intended website.

## HTTP and HTTPS behavior

- The Android Rust origin is HTTP; it does not itself terminate public TLS.
- Cloudflare terminates public HTTPS at its edge and forwards to the local origin.
- Whether public HTTP redirects to HTTPS is controlled by Cloudflare zone/edge settings. Pocket Host does not currently configure this policy.
- The v0.1.0 target is HTTP accepted and redirected to HTTPS by default. Plain HTTP content serving is an explicit owner opt-in with a warning.
- Do not report HTTPS as verified until an external client confirms a valid certificate for the exact domain and receives the expected website content.

## Security and operations

- Treat the tunnel token as a password; never paste it into logs, issue reports or screenshots.
- Token encryption at rest is present; test restore, token rotation, invalid token, corrupted Keystore state and removal.
- Do not point a public hostname to the local management API, browser dev server or fleet control API.
- Use Cloudflare Access if private-site protection is desired at the edge; Pocket Host also has local site-level visitor access modes, but those must be tested through the proxy.
- Android Doze, battery optimization, mobile data loss, thermal pressure and OEM process management can interrupt the connector.
- Cloudflare failure must not stop local/LAN website hosting or the independent AssayFlux Relay Node.
